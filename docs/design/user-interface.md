# User Interface

## Emberwood UI family

All implemented modals inherit one UI family: 96-99% ink panels, six-pixel corners, 18 px normal button text, minimum 44 px targets, cream/gold pressed state, and a four-pixel focus outline. The HUD includes an observed health bar; its concise title remains inside the left safe panel. Opening equipment suppresses transient encounter/rift overlays so they cannot cover comparison content.

Rarity is always written by name in addition to color. Salvage confirmation changes the focused action to `> CONFIRM DESTROY +N` and shows a full warning sentence, so destructive meaning is not color-only. The longest Legendary comparison stays in the bounded scroll region, with LB/RB scrolling and every action inside 1280x800.

The reference viewport is 1280x800. HUD information must be legible, anchored safely, and non-authoritative. The normal status panel is bounded to the upper-left 410x304 safe area and observes health, wood, stone, and equipment through state-change signals rather than frame polling. Its health fill is capped at 260 pixels so it retains visible padding inside the panel; its weapon line names the equipped family and item, with detailed values directly above it. The upper-right onboarding strip presents controller actions only, while a bottom-safe contextual prompt names the nearest usable target and its shared `[A]` action without obstructing the center of play. Keyboard bindings remain supported but are not customer-facing HUD copy. Menus require explicit controller focus and no mandatory text input or mouse hover.

The equipment modal browses every collected item with Previous/Next controls and a selected-position count. A pure presenter supplies level, slot, rarity by both name and color, base weapon/stat values, every formatted ordinary affix with category, and the full legendary behavior. Comparison names both candidate and same-slot equipped item, includes both affix/behavior sets and signed gameplay-stat changes, and never invents an item score. An empty slot is labeled explicitly. Long content wraps inside a bounded scroll area; LB/RB scroll its details without a pointer. Equip, Unequip, and Keep/Unfavorite are direct controller actions; Salvage requires a second focused confirmation that names the reward and warns that the item will be destroyed. Equipped and favorited items visibly reject salvage. Opening the modal focuses a valid action and suspends player/enemy movement. Explicit focus neighbors recover when an action disables itself.

The workbench modal browses the validated recipe registry with a position indicator. It shows the selected permanent effect, owned versus required resources, affordability, and success or rejection feedback. When a recipe is unaffordable, focus starts on recipe browsing; completion moves focus to an unlocked action. Only one modal can be open, and closing restores gameplay.

The normal play HUD deliberately contains no game-name banner and no numeric resource, equipment, or derived-stat list. It retains only compact, percentage-free health and mana bars plus contextual objective/interaction feedback. The inventory owns the complete numeric summary (resources, survival supplies, prepared harvests, salvage, health, mana/regeneration, damage, speed, critical chance, gathering power, pickup radius, and production speed) and item comparison. Its dedicated technology sub-page renders the complete twelve-node graph across four tiers with semantic icons, routed prerequisite connections, and learned/ready/gather/locked states. Previous/Next browsing remains controller-first; the selected node always names its tier, full effect, prerequisites, exact cost, and craftable recipe unlocks before confirmation. Back returns focus to the inventory entry point.

One compact field line below the vitals names expedition day, clock, phase, biome weather, and remaining Shelter seconds. It contains no authoritative state and updates from the one-second expedition timer; dawn/day/dusk/night also receive distinct world-light colors while CanvasLayer UI remains readable.

An active Wayfinder contract occupies one additional concise field line: title plus numeric progress, or an explicit return-to-Mira instruction. Talking to Mira opens an opaque controller modal with issuer, biome/weather context, full objective, progress, reward classes, focused Accept/Claim, and a separate Not Now action. Cancel closes without mutation; Not Now explicitly declines an unresolved offer. Equipment inventory owns the Expedition Mark count beside other survival progression values.

An installed-island story uses one separate concise objective line and Tala's opaque controller modal. The offer identifies the biome/level and complete reward classes; the branch screen explicitly states that restoration yields a stronger shard while purge yields epic equipment before either action commits. After claim, the same modal becomes a three-offer Expedition Mark exchange. Visible focus recovers after a purchase disables its button, cancel returns to play, and the world—not the HUD—owns every story and currency mutation.

During the Forest Warden climax, Tala uses the existing bounded encounter line for three event-driven hints only: sideways root-lane counterplay, the faster half-health phase, and the branch-aware victory confirmation. These messages are not polled or repeated per frame. The field objective remains `DEFEAT THE VERDANT WARDEN 0/1`; attack safety is communicated spatially by the lane itself rather than by circular actor overlays.

The inventory also exposes a Journey Journal entry beside Technology. Its eleven ordered milestones show name, active/completed state, full instruction, exact progress, and one-time reward. Previous, Next, Back, and cancel all work without pointer input. The field objective mirrors only the next incomplete milestone so it remains concise.

The system modal exposes a single local Save and Load slot, displays schema version 11 and explicit results, and focuses Save when opened. Opening it suspends movement, combat, and production. It requires no pointer or text entry.

The M2 equipment layout is visually checked at 1280x800. Long affix and legendary descriptions wrap inside an opaque panel, all actions remain in frame, and controller focus is visible without relying on hover.

The island-shard modal browses owned shards and three stable world slots. It displays biome, level, size, rarity, resources, enemies, positive modifiers, negative risks, special encounter, expected rewards, and any adjacency benefit/price before confirmation. Separate shard and slot controls, Install, Remove, and Cancel are fully focus-connected. Replacement/removal require a second confirmation and explain that active entities will be cleared. The 1280x800 layout wraps all modifier and synergy text without clipping.
