# Testing Strategy

The project uses a small dependency-free Godot test harness under `game/tests/` to avoid an unreviewed dependency. Unit tests cover pure rules; integration tests instantiate cooperating nodes; simulation tests drive fixed actions and assert player-facing milestones. All procedural assertions use fixed seeds. Visual scripts produce reproducible 1280x800 artifacts for manual inspection.

Every CLI test command writes a JUnit report under `build/test-results/`; set `TEST_REPORT_DIR` to choose another directory. A missing script, compile failure, assertion failure, incomplete assertion contract, or report-write failure returns a nonzero exit code. `validate` imports the project, runs static validation, and then runs the complete test suite.

CI runs import, static validation, unit, integration, and simulation steps separately so logs identify the failing layer. JUnit reports and successful platform exports are retained as workflow artifacts.

To add a test, create a deterministic script in the matching `game/tests/<layer>/` directory, implement `run(support)` for unit tests or `run(support, scene_tree)` for asynchronous scene tests, and register its path and exact assertion count in `game/tests/run_tests.gd`. Run the narrow layer first, then `make validate`.

The M1 simulation repeats the same fixed-seed route from spawn to tree, stone, first Slime, weapon pickup/equip, and second Slime. It asserts exact repeatability, inventory totals, two deaths, one optional item drop, canonical item state, and fewer equipped hits. The M1 scene contract separately measures coalescing 100 resource drops and validates actual input actions, camera behavior, interaction, attack cooldown, and Slime state.

M2 unit coverage validates all registries, rarity contracts, affix eligibility/conflicts, JSON round trips, six-slot stat recomputation, protected salvage, and modular legendary lifecycle. A fixed-seed 10,000-item run checks every generated item for duplicates, conflicts, eligibility, and serialization. Integration tests exercise the actual sword, bow, and wand target shapes, controller equipment flow, schema-4 migration, each new legendary world effect, temporary cleanup, and a 200-drop cap scenario. The M2 simulation generates a mixed six-slot loadout and triggers Chain Mining, Burning Smelter, and Living Arrows with exact metrics.

M3 unit coverage validates the Node-free archipelago, deterministic neighbors, shard/runtime separation, required definition fields, modifier component lifecycle, all three adjacency tradeoffs, schema-5 persistence, and schema-4 migration. A 10,000-shard fixed-seed generation checks all six biomes and paired risk/reward validity. Integration exercises controller preview/slot focus, transactional failure, physical Forest content, all cleanup/protection rules, Moonleaf crafting, adjacency preview, destroyed resource and reward restoration, and replacement warnings. The fixed M3 simulation performs the complete obtain-preview-place-synergize-save-replace-remove route.

M4 unit coverage validates registry IDs and atomic recipe plans; preview-free placement; FPS-independent mill conversion; collector rarity/ownership/radius/batch limits; safe overflow; clock rollback/four-hour cap; +0…+10 cost/power/preservation; and schema-5→6 migration. Integration performs controller placement and rotation, physical multi-building flow, rare/player-owned exclusions, blocked output, protected upgrade, and save/load continuation. The fixed M4 simulation repeats the full manual-resource→automation→upgrade route and prints `M4_METRICS`.
